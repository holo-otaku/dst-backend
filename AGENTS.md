# Agent Guide: DST Backend

Flask REST API for the DST product-query system. This file is the backend's own guide; where `../AGENTS.md` disagrees on commands or tooling (Pipenv, MySQL, `config.py.example`, "no tests"), this file wins.

## 1. Commands

Python 3.12, managed with **uv**. Run everything from `backend/`.

| Task           | Command                                                       |
| :------------- | :------------------------------------------------------------ |
| **Install**    | `uv sync` (includes the dev group)                            |
| **Dev**        | `flask run`, or `python app.py` (also seeds permissions, admin role and `admin`/`admin`) |
| **Tests**      | `uv run pytest`                                               |
| **One test**   | `uv run pytest tests/unit/test_product.py::test_copy` |
| **Lint**       | `uv run pycodestyle .`                                        |
| **Format**     | `uv run autopep8 --in-place --aggressive --aggressive <file>` |
| **Migration**  | `flask db migrate -m "..."` then `flask db upgrade`           |
| **Local DB**   | `docker compose up -d` (PostgreSQL 18; the backend container runs `flask db upgrade`) |
| **Prod**       | `gunicorn --config gunicorn.conf.py app:app`                  |

- Swagger UI: `http://127.0.0.1:5001/api/docs/` (needs `ENABLE_SWAGGER=true`). The spec is generated by flask-smorest from each router's marshmallow schemas (`@blp.arguments`, `@blp.response`, `errors()` in `routers/schemas.py`); there is no hand-written spec. Every router is a `flask_smorest.Blueprint` registered with `api.register_blueprint`. Put `@check_permission` above `@blp.arguments` so permission is checked before the body; public routes add `@blp.doc(security=[])`.
- `config.py` (class `Config`) is local and holds secrets. Never commit it, and there is no example file.
- Add dependencies with `uv add` so `uv.lock` stays in sync. CI runs `uv sync --frozen`.

## 2. Architecture

- **Layers:** `routers/` (thin blueprints) → `controller/` (all logic, returns Flask responses) → `models/` (SQLAlchemy; shared `db` in `models/shared.py`). Blueprints are registered in `routers/routes.py`, one url_prefix per resource.
- **Router pattern:**

  ```python
  @products.route("/search", methods=["POST"])
  @check_permission("product.read")
  def read_multi_product():
      data = request.get_json()

      return read_multi(data)
  ```

- **Response shape:** `make_response(jsonify({"code": 200, "msg": "Success", "data": ...}), 200)`. Errors use the same shape with the matching status (`400`, `404`, ...). Keep stack traces out of responses.
- **Permissions:** `check_permission("x.y")` reads the permission strings in the JWT, not the DB. New permissions go in `permissions_table` in `models/mapping_table.py`.
- **Middleware path skips are substring matches.** The activity log skips paths containing `login`, `refresh`, `log`, `health`, `image`, `/api/docs`; the token-version check skips `/login`, `/refresh`, `/health`, `/api/docs`, `/static`. Check a new route path against both lists.
- **Product attributes:** `Item.attributes` is JSONB `{str(field_id): value}`. Read, write and compare values through `controller/field_value.py` (`stored()`, `sql()`, `present()`), not ad hoc. Product search/export SQL lives only in `controller/product_query.py`.
- **ERP:** `controller/erp.py` talks to an external MSSQL via pyodbc. It is read-only and never available in tests.

## 3. Code Style

- PEP 8 via pycodestyle and autopep8; run both on files you touch.
- Imports: stdlib, then third-party (Flask, SQLAlchemy), then local modules, with a blank line between groups.
- `snake_case` for functions, variables and files; `PascalCase` for classes and models.
- Module-private helpers use a `__name` prefix (e.g. `controller.user.__denied`).
- Wrap DB and file operations in `try/except` and return a proper status code; no bare `except:` and no `print` (use `current_app.logger`, which `modules/logger.py` writes to `logs/app.log`).

## 4. Tests

- Live in `tests/unit/`, pytest functions.
- Controller tests: the `app` fixture in `tests/unit/client.py` (in-memory SQLite, no routes or middleware). Call controller functions inside `app.app_context()` and mock with `unittest.mock.patch`.
- Route-level tests: the `ctx` fixture in `tests/unit/test_security_fixes.py` registers routes and middleware and mocks `read_erp` (see `test_api_smoke.py`).
- Set `TEST_DATABASE_URI=postgresql+psycopg://...` to run against PostgreSQL. CI runs the suite on both SQLite and PG, so avoid SQLite- or PG-only behaviour.

## 5. Schema Changes

1. Edit the model under `models/` (make sure `models/model.py` imports it).
2. `flask db migrate -m "..."`, then review the generated file in `migrations/versions/`.
3. `flask db upgrade` locally, then run the tests.

## 6. Pre-commit Checklist

- `uv run pytest` passes.
- `uv run pycodestyle` is clean on the files you changed.
- A changed route's schemas match what the controller reads and returns.
- Migration included for any model change.
- Conventional commit messages (`feat(db): ...`, `fix: ...`, `test: ...`).
